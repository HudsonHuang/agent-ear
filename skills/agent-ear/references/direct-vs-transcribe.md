# 直接 ask vs 先转录再 ask：差多少，为什么

> 同一批 40 条子集（MMAU-Pro 30：sound/music/speech 各 10；CMDAR 10），thinking 256。  
> 不是 180 条全量；数字用于看**方向**，不是最终榜单。

## 1. 四种路径

| 路径 | 做法 | 40 条准确率 |
|---|---|---:|
| A. 直接 ask | 音频 + 题 + 选项 → Omni，直接答 | **87.5%** |
| B. 一次调用：详细转录 + 回答（40 条子集） | 音频 + 题 → Omni，同时返回 transcript/events/music + answer | **90.0%** |
| B. 一次调用（180 条全量） | 同上 | **80.0%** |
| C. 转录后 ask（强文本模型） | 先 Omni 详细转录 → `context.md` → qwen3.8-max 答 | **77.5%** |
| D. 转录后 ask（普通文本模型） | 同上 → qwen-plus 答 | **65.0%** |
| E. 压缩 note 后 ask | 只给 ~400 字 note → qwen-plus | 55.0% |

**结论**：

1. **单问题最高准确率还是 A（直接 ask）**：180 条 87.2%。
2. **B 在 40 条子集上 90%，但 180 条全量只有 80.0%**：不能把子集结果当结论。B 的 MMAU 69.0、CMDAR 93.8，还有 2 条 JSON 解析失败；比 A 低 **7.2pp**，成本却是 A 的约 8 倍。
3. **C/D 明显低于 A**：强文本模型差 **10pp**，普通文本模型差 **22.5pp**。
4. **E 最差**：把音频压成 400 字 note，信息损失不可逆。
5. **“一次调用全都要”有 dual-task 代价**：模型要同时做长转录和回答，答案注意力/输出预算被分走；JSON 变长还容易截断/格式错。

## 2. 差距主要在哪

| domain | A 直接 ask | C 转录+强文本 | D 转录+普通文本 | B 一次调用 |
|---|---:|---:|---:|---:|
| sound | 70% | 40% | 20% | 80%（40 条）/ 63.3%（180 条） |
| music | 100% | 80% | 70% | 100%（40 条）/ 73.3%（180 条） |
| speech | 80% | **90%** | 80% | 80%（40 条）/ 76.7%（180 条） |
| CMDAR | 100% | 100% | 90% | 100%（10 条）/ 93.8%（80 条） |

规律很清楚：

- **sound / music：直接听赢得最多**（+30–50pp）。这些题问的是音色、乐器、效果、环境声、音乐结构，转录文本里根本没有这些信息。
- **speech：转录后反而可能更好**（90% vs 80%）。题目问“说了什么/什么意思/社交意图”，文本足够，强文本模型的世界知识和推理还能补。
- **CMDAR 场景/社交推理：接近饱和**，两种路径都能到 90–100%。

## 3. 为什么

### 3.1 转录是信息瓶颈

ASR 只保留“词”，丢掉：

- 语气、情绪、重音、停顿、笑声、哭腔、耳语；
- 说话人音色、年龄感、口音；
- 背景声、音乐、乐器、音效、空间感；
- 声音事件的时间边界和重叠关系。

AED 事件标签又只有粗粒度（`Laughter` / `Music` / `Speech`），且可能漏召回。文本 LM 再强，也不能从“laughter”三个字里听出“是苦笑还是大笑”。

### 3.2 问题是“先转录”之后才来的

先转录时，模型不知道用户会问什么，容易省略“后面问题需要的细节”：

- 问“0:08 进入的是什么乐器”，转录只写了人声；
- 问“这个音效像什么”，事件只写了 `Mechanism`；
- 问“哪段是副歌”，转录没有 section。

直接 ask 可以**带着问题听**，把注意力放在相关声学证据上。

### 3.3 错误不可逆

ASR 把名字、同音词、数字听错后，文本 LM 没有音频可回查；直接 ask 可以用声学上下文纠正。

### 3.4 选项对比需要声学证据

四选一里经常是“相似但不同”的选项（乐器、效果、音效）。文本描述往往只给一个粗标签，无法区分；直接听可以把选项和声学细节对齐。

### 3.5 文本模型不是没用

- 对 speech/语义/社交推理，文本模型可以用常识、上下文、选项排除，甚至超过直接听。
- 对多问题场景，转录一次可以问很多次，边际成本低。
- 对长音频，转录+文本比每次把长音频塞给 Omni 更可控。

## 4. 决策建议

| 场景 | 推荐 |
|---|---|
| 只问一次，要最高准确率 | **`agent-ear ask` 一次调用：详细转录 + 答案（B）** |
| 要问多个问题，或要留时间轴 | `agent-ear listen --mode basic` 一次转录 → `agent-ear ask --score` 多次问（C），接受 10–20pp 差距 |
| 只要字幕/说话人/时间戳 | `agent-ear listen --mode basic` 或 `precise`，不需要 Omni answer |
| 声音/音乐/音效题 | 直接 ask 或 B；不要只靠转录 |
| 语音内容/语义/社交题 | 转录 + 强文本模型即可，甚至更好 |
| 精确打轴/卡点 | `precise`：Qwen 词级 + BEATs 40ms + Beat This! |

**一句话**：  
**直接 ask 是“带着问题听”，转录后 ask 是“先听完再回忆”。前者在单问题/声学题上赢；后者在多问题/时间轴/成本上赢。一次调用同时做详细转录和回答（B）听起来最美，但全量实测会掉 7pp，因为 dual-task 和 JSON 长度都会伤答案；要同时拿两者，最好还是“分析一次 + 文本 LM 多问”或“两次调用”，而不是硬塞进一个 JSON。**
