# hearing.md（示例）

> 这是 Skill 给 LM 读的「一页听觉记录」，不是完整 JSON。它以 `audio-score` 为事实源生成，每句都带时间戳。下面用一段虚构的 30 秒片段演示目标形态。

## 一句话

两位女性在室内聊天，背景是 92 BPM 的轻钢琴；00:12.3 出现一段 2.4 秒的笑声，落在上一句包袱结束后约 0.3 秒；00:21.0 音乐切到鼓点更强的副歌，00:21.4 有一次画面切镜，切点比最近的 downbeat 晚约 180ms。

## 时间轴

| 时间 | 听到什么 | 显著性 |
|---|---|---|
| 00:00.0–00:05.2 | S0 说话，语速偏快；背景钢琴 intro，无鼓 | 人声前景 |
| 00:05.2–00:08.8 | S1 接话，两人有 0.4s 重叠；S0 笑了一声（短，0.3s） | 人声前景 |
| 00:08.8–00:12.0 | S0 讲完一句，停顿 0.6s；钢琴保持 | 停顿 |
| 00:12.3–00:14.7 | **笑声**（两人一起，2.4s），压住钢琴；无语音 | 笑声前景 |
| 00:14.7–00:20.9 | S1 继续说话；钢琴进入 verse，鼓点进入 | 人声前景 |
| 00:21.0–00:30.0 | 副歌：鼓点加强，BPM 仍 92；S0/S1 交替，情绪更兴奋 | 音乐+人声并重 |

## 联合观察

1. **笑点位置**：笑声 `ev_0012` 在 `sp_0008` 结束后 320ms 出现，和包袱之间没有重叠；这是一次「说完—停—笑」的节奏，不是抢话。
2. **音乐与语音**：00:12–00:15 笑声期间，音乐没有被压低（没有 ducking），所以笑声是前景；00:21 之后人声仍然清楚，但鼓点能量上升，音乐从背景变成并重。
3. **卡点**：00:21.4 的切镜落在副歌第一个 downbeat（00:21.22）之后 180ms；如果按 downbeat 对齐，切点应前移 180ms。这个误差人耳能感觉到「稍微拖了一点」。
4. **说话人**：全段只有 S0/S1 两个匿名说话人；00:05.2–00:05.6 有 0.4s 重叠，Qwen 的 `speaker_id` 在这段置信度偏低，建议人工复核。
5. **情绪曲线**：00:00–00:12 轻松、语速中等；00:12 笑声是第一个峰值；00:21 副歌 + 切镜是第二个峰值。适合把这段当「起—承—转—合」的转场。

## 可下刀

- 卡点混剪：把切点从 00:21.40 挪到 00:21.22（最近 downbeat），或挪到 00:21.67（下一拍）做「延迟感」。
- 高光切片：00:11.8–00:15.2 是「包袱 + 笑声」的完整单元，前后各留 0.3s 更自然。
- 字幕：00:12.3 加 `[笑声]`；00:21.0 加 `[音乐渐强]`；00:05.2 的重叠段需要双色/双行。

## 不确定

- 00:05.2 的 0.4s 重叠：是抢话还是笑声叠进来，`speaker_conf=0.42`，建议听原声。
- 00:21 的段落标签是 `chorus`，但这段只有 9 秒，All-In-One 的段落置信度 0.61；如果用于正式剪辑，建议人工确认。
- 背景钢琴的乐器识别只到「钢琴/弦乐」级别，没有更细的编曲信息。

---

**这份记录的用法**：LM 先读「一句话 + 时间轴」判断要不要深挖；需要精确剪辑时再 `ear context --query "00:21 切点"` 拉词级/节拍级证据。它不需要一次读完 1 小时的 JSON。
